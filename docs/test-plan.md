## 验收门槛

1. 原版调查：记录实际看到的页面、入口、操作及状态变化并附证据。未知项保持待调查。
2. 范围确认：为调查后的功能分配编号，关联原版证据、实现负责人、接口及页面用例。不得把未确认玩法写成既定需求。
3. 单项验收：同一功能的接口、页面点击与最终状态均符合确认要求才能通过；仅有代码或接口测试不等于完成。
4. 集成验收：验证连续操作、刷新及已确定需要持久化的状态在服务重启后的结果。
5. 完整性审查：逐项对照范围矩阵、原版证据和差异记录；范围内不得有未实现、未测试或阻塞项，无法核实的范围必须披露，不得以部分演示声称完整复刻。

## 接口测试

接口测试仅针对本地服务。具体端点、参数、响应及业务断言在调查与接口契约确定后补充。

- 状态变更记录操作前查询、请求、响应、操作后查询，核对资源增减与关联状态。
- 对已确定需要持久化的状态，验证刷新读取及服务重启后读取一致。
- 按已确认业务规则验证重复请求、失败操作与边界，不编造原版规则或因测试计划擅自增加校验。
- 若实现使用 WebSocket，记录已确认消息类型与顺序；HTTP 握手成功不能代表业务通过。
- 测试数据须可重复准备，记录数据版本与前置状态。

## 页面点击测试

恢复内部浏览器能力后，主代理分配独占页面操作时段，避免代理同时导航或更改共享页面。

- 实际点击入口、按钮和弹窗，记录点击步骤与可见结果；直接调用接口、内部函数或修改存档不能替代页面操作。
- 核对展示、资源变化、返回导航及刷新结果，与接口查询交叉验证。
- 截图记录视口、页面状态及时间；随机结果、动画和加载状态注明条件，不能只靠像素差异判断业务正确性。
- 必要时记录控制台错误及失败请求；证据不得含账号口令或会话令牌。
- 如需原版登录，展示支持的二维码或说明内部浏览器登录步骤，等待用户完成，不绕过登录。

## 证据与状态

`acceptance-matrix.csv` 是验收索引。后续新增调查所得功能须使用独立编号并关联证据，不覆盖初始要求。

每条执行证据包含：用例编号、功能编号、Git 提交、测试时间与 Australia/Perth 时区、原版证据编号、环境、前置数据、步骤、预期与实际结果、证据路径、执行人。接口证据补充请求摘要、响应及前后状态；页面证据补充视口、点击步骤与截图。失败项关联缺陷及复测记录。

| 状态 | 定义 |
| --- | --- |
| NOT_RUN | 尚未执行，不能推断结果 |
| BLOCKED | 存在明确阻塞，记录原因及恢复条件 |
| FAIL | 已执行且不符合确认要求 |
| PASS | 已执行且证据支持通过 |

初始矩阵全部为 NOT_RUN 或 BLOCKED。必要接口与页面用例均通过后，整体功能才可标记 PASS；纯交付项依据对应交付证据验收。
