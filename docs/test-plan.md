## 验收门槛

1. 原版调查：记录实际看到的页面、入口、操作及状态变化并附证据。未知项保持待调查。
2. 范围确认：为调查后的功能分配编号，关联原版证据、实现负责人、接口及页面用例。不得把未确认玩法写成既定需求。
3. 单项验收：同一功能的接口、页面点击与最终状态均符合确认要求才能通过；仅有代码或接口测试不等于完成。
4. 集成验收：验证连续操作、刷新及已确定需要持久化的状态在服务重启后的结果。
5. 完整性审查：逐项对照范围矩阵、原版证据和差异记录；范围内不得有未实现、未测试或阻塞项，无法核实的范围必须披露，不得以部分演示声称完整复刻。

## 1:1 对照验收标准

以已取证原版为基准逐项验收。正式接受的是画面、交互、规则与状态行为均有证据的对应实现；用户授权的本地测试充值直接成功属于明确差异，应单独记录。尚未观察到的玩法、动画时长、随机分布及隐藏规则均标待调查，不能擅自设定。

| 维度 | 执行方法 | 接受依据 |
| --- | --- | --- |
| 静态画面 | 原版与本地采用同一视口、缩放、设备像素比、页面及角色状态；并排展示并保存叠图或差异图 | 核对布局、字号、文案、颜色、图标、素材、层级、遮挡与滚动位置；记录每处差异及是否获确认 |
| 动画 | 同一触发动作和起始状态，采集原版与本地连续帧或录像，按动作起点及关键帧对齐 | 核对顺序、位移、播放节奏、特效出现和消失、结束状态；无原版样本时不得判通过 |
| 交互 | 对同一入口执行相同步骤，包括已观察的关闭、返回、重复点击及禁用状态 | 导航、响应结果、弹窗内容与可点击区域符合原版证据；加载差异注明环境条件 |
| 数值与规则 | 固定已确认的前置资源与配置，记录原版变化和本地接口前后状态，再从页面复核 | 可确定的消耗、奖励、显示与状态转移逐项一致；随机行为仅按已证实规则验收，不要求无依据的单次结果一致 |
| 持久化 | 对已确认会保存的状态操作后刷新及重连，本地另验证服务重启 | 页面与接口读取结果一致，符合原版已观察的保存行为；不猜测原版后端实现 |

不预设像素百分比、动画毫秒阈值或数值容忍区间。先保留原始画面对照及环境数据，对动态文字、时钟等不可固定内容单独说明；确需容差或排除区域时须有测量依据并由主代理取得用户确认，不能自动忽略差异。静态截图通过也不能替代动画与交互验收。

每个可操作功能至少形成一组关联证据：原版操作与预期、本地接口验证、本地真实页面点击、最终状态查询。用例编号相互关联，独立 QA 检查三方状态一致。无服务端交互的纯展示项可注明接口不适用及依据，但不得把会改变游戏状态的功能改为不适用以逃避验证。

## 独立 QA 角色与拒收规则

独立 QA 代理不以开发代理的自测声明代替执行。开发代理交付可运行版本、确定的测试数据及实现说明后，QA 根据原版证据独立执行用例、保存结果、提出缺陷并复测。主代理担任大脑与监控者，安排代理及浏览器独占时段、审核证据和差异，统一决定是否满足交付门槛；开发代理不得自行关闭 QA 缺陷。

| 等级 | 判定依据 | 处置 |
| --- | --- | --- |
| P0 | 本地测试产生真实扣款、不可恢复存档损坏或重要数据泄露 | 停止相关流程，保留证据并优先修复；阻止交付 |
| P1 | 已确认主要流程不可完成，资源或奖励结算错误，关键状态丢失 | 阻止相关功能及整体完成声明，修复后双层复测 |
| P2 | 可完成流程但交互、画面、动画或规则存在可重现偏差 | 记录原版对照并修复；未解决差异不接受为 1:1 |
| P3 | 不影响业务结果的局部显示或文案偏差 | 仍需修复或用户明确接受差异，不能静默忽略 |

以下情况拒收：功能范围不明却宣称完整；原版基准缺失；已有入口使用占位或无效操作；未实现功能标 PASS；状态变更缺少接口或真实点击证据；截图状态不同仍声称一致；未解决差异或缺陷无用户明确接受记录；刷新或重启后状态不符合已确认行为；把环境恢复、原版登录成功或选服截图当成本地游戏功能通过。

BLOCKED 与 NOT_RUN 不等于失败，但同样不能支撑交付通过。任何例外须关联用户确认及影响范围，不能由 QA 自行降低标准。
