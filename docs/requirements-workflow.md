# 需求分析与原版取证工作流

目标：以用户指定的 7k7k《自在江湖》为唯一验收对象，逐项建立 1:1 复刻规格。只有证据已覆盖、实现已完成且接口与页面两条验收均通过的项，才可标记完成。本文是执行规则，不代表完整范围已经确认。

## 当前基线

按主代理本次已确认结果记录：原版为 Unity WebGL；已注册并登录平台，用户已同意游戏协议；停留在选服阶段，尚未进服。选服版本为 `1.1.57_181509.181509.ss`，推荐服务器为 `凌云20服 [L20]`。旧的“登录待批准”状态已过时，不再作为阻塞项。

选服证据：`EVD-0001`，见 [选服截图](evidence/original-server-select.png)。技术类型及登录状态为主代理观察结论，不应声称全部由单张截图证明；后续需要可复查证据时补充脱敏记录。

原版入口及公开资料见 [资料证据](reference-evidence.md)。禁止把其他渠道资料直接转为实现要求。游戏内系统、入口和规则尚待进服调查；下列采集类别是检查清单，不表示系统已存在。

## 角色、交接与权限

| 角色 | 可执行职责 | 交付及交接 |
| --- | --- | --- |
| 主代理：大脑与监控 | 维护版本基线、任务队列、依赖和阻塞；指定浏览器唯一操作者；审查证据与范围，分派实现与测试，统一集成 | 每项任务写明负责人、规格编号、输入、产物、完成条件；证据不足退回调查 |
| 原版取证代理 | 在内部浏览器按指定账号与服务器采集可见行为；记录前置状态、点击路径、画面变化及可观察请求；标注不可访问或未解锁项 | 提交脱敏证据包、操作记录和未知项；不推测服务器内部算法，不使用宿主机浏览器 |
| 需求分析代理 | 将证据转成界面、状态、规则与验收规格；核对跨页面和跨会话行为；检查证据是否足以支持结论 | 提交功能规格和追溯表；交给主代理审核后供实现、测试共用 |
| 实现代理 | 仅依据已审核规格开发；发现矛盾、隐藏规则或缺失状态时回报 | 提交实现与规格对应关系，不自行补成常见武侠玩法 |
| 接口与页面测试代理 | 分别从服务接口和内部浏览器点击验证行为与持久化；对比同一版本基线 | 提交双轨结果、差异证据和复现步骤；一轨通过不得替代另一轨 |

同一内部浏览器一次只交给一个代理，交接记录当前页面、服务器、角色和未完成操作。本文编写代理不操作浏览器、不提交 Git。代码与文档由主代理统一审查提交。

## 采集步骤和覆盖清单

1. **建立会话基线**：记录原版版本、服务器、角色进度、采集时间及时区、窗口尺寸、缩放和音量；账号仅用别名。每次切服、重置或版本变化建立新批次，禁止混用数值样本。
2. **先走完整路径**：从进服开始记录可达页面、弹窗、返回路径和引导；为每个入口建立清单，未解锁和未出现的项标记未知。
3. **按功能采样**：记录操作前状态、输入、过程、结果及可观察接口；覆盖成功、失败、取消、重复操作和刷新恢复。会改变原版稀缺资源的实验先由主代理确定安排，不把本地测试支付规则用于原站。
4. **形成规格并复核**：需求代理把事实、推断和未知分别写明，主代理确认可实施部分后派发；测试代理提前补足可检查的验收条件。

| 类别 | 必采内容 | 产物与限制 |
| --- | --- | --- |
| 画面 | 页面层级、背景、角色、字体、图标、颜色、尺寸、间距、遮挡、滚动、响应式表现和加载状态 | 同尺寸截图及区域标注；未看到的界面不得用资料图代替 |
| 动画 | 入场、移动、战斗、受击、技能、转场、奖励和特效的触发、顺序、持续时间、循环与中断 | 可获取时保存录像/连续帧及时间点；不能仅凭静态图认定时序 |
| 音频 | 可听见的背景音乐、按钮/战斗音效、触发时机、循环、叠加、静音与音量设置 | 记录播放条件及可用录音；无录音或音轨不可访问则保留未知，不默认静音 |
| 操作 | 点击/拖动/长按等实际支持手势、热区、返回、连点、防重、自动与手动行为 | 每条路径可重放；只记录原版实际出现的交互 |
| 数值 | 属性、等级、消耗、收益、战斗结果、冷却和概率展示；记录操作前后差值 | 区分界面明示规则与样本推断；有限抽样不能证明隐藏概率或精确公式 |
| 持久化 | 刷新、断线重连、重新登录后的资源、进度、设置与领取状态 | 操作前后快照；标明账号/角色/服务器归属，不猜测数据库结构 |
| 多人 | 如有可达入口，核对组队、聊天、排行、交易、同场可见性及同步规则 | 需相应账号和场景才实验；看见入口不等于验证同步，未出现不等于不存在 |
| 时间与活动 | 如有，记录开始/结束、重置、倒计时、跨日、离线收益和服务端时间表现 | 记录绝对时间与时区；未等到边界保留未知，不能用改本机时钟推断原站行为 |
| 接口 | 已观察到的请求/响应字段语义、状态变化、错误与重复请求行为 | 只保存脱敏摘要；看不到原版接口时明确缺口，不伪称协议已验证 |

## 编号、证据与功能规格模板

编号保持稳定且不复用：`EVD-0001` 为证据、`REQ-0001` 为功能规格、`UNK-0001` 为未知项、`DIFF-0001` 为实现差异；截图、录像或脱敏记录关联编号。每份证据写明版本批次、采集人、时间、前置状态、重现路径、观察结果及文件位置。索引只写相对路径和无认证的公开入口；严禁保存密码、验证码、token、Cookie、Authorization、含认证参数的游戏 URL 或未脱敏请求日志。

每个功能规格使用以下字段，未知值直接填写关联 `UNK`，不得留给实现代理猜测：

```text
REQ-编号 / 功能名称 / 状态：待证据 | 可实施 | 待验收 | 已验收
原版批次：版本、服务器、角色进度；范围与可达入口
证据：EVD 编号；事实 / 推断 / 未知分栏
前置条件与状态：资源、权限、进度、时间条件
操作：输入、点击路径、取消/返回/重复操作
规则：状态转换、消耗与产出、错误、并发/时间行为
表现：画面基准、动画时序、音频触发
持久化：刷新、重连、重新登录及作用范围
接口契约：本地请求/响应与状态；原版可观察证据、缺口
验收：API 用例 + 页面点击用例 + 预期状态/视觉结果
差异与未知：DIFF / UNK 编号、影响、负责人
```

测试环境充值直接成功属于用户明确指定的本地行为例外，必须在对应规格中单列，覆盖订单成功、奖励到账、重复提交及刷新后的状态。它不是原版规则证据，也不意味着原站支付可跳过或应进行真实充值。

## 未知项关闭与交付门槛

每个未知项记录问题、影响范围、所需证据、负责人和下一步。关闭必须满足以下之一：取得同一版本可复查证据并更新规格；通过足量观察确定可观察规则且明确不能证明的内部机制；或用户明确调整验收范围，并保留范围变更记录。未解锁、未等待到活动、暂未观察到、资料里未提及均不能作为“不存在”的关闭依据。无法验证的项持续标记未知；模拟行为不得冒充原版一致。

交付前检查：每个已验收功能可追溯到证据；API 与页面点击结果同时通过；画面、动画、音频、数值与持久化差异已记录；存在的多人和时间行为已有对应验证，或明确未验收；无凭证和认证 URL 入库。只有完整范围已建立且未解决差异、未知与测试缺口不再影响该范围时，才可由主代理宣称对应范围达到 1:1；阶段成果不得标作完整复刻。
