# 自在江湖 1:1 复刻总计划

更新：2026-10-12（Australia/Perth）。本会话负责总协调；本文是执行计划，不是完成声明。

## 目标与验收边界

目标是用户指定 7k7k 渠道《自在江湖》的 1:1 复刻，不以同题材、相似风格、简化玩法或静态演示代替。逐项对照原版的界面布局、素材、字体、动效、音频、操作流程、反馈、规则、数值、资源变化和存档行为。多人、活动、跨服等先确认是否存在，再纳入实际范围，不凭名称虚构。

测试阶段充值直接成功是用户指定的行为差异：本地支付适配器完成订单与权益发放，不进行真实扣款。除此之外发现差异须记录并处理，代理无权自行降低还原要求。

未开放系统、无法观测的概率与后台规则必须列为未知；不能把“已验证范围完成”描述成“完整 1:1 完成”。是否真正达到 1:1 取决于证据与验收结果，不能在调查前承诺。技术选型不得降低验收目标。

当前工具允许主会话加三个代理同时运行，不是六个角色都同时开工。现有 game_research 承担需求，repo_architect 承担架构与交接，qa_planner 承担独立验收规划。后续按阶段轮换：调查时“需求+资源+QA”；开发时“客户端+服务端+QA”；扩展时安排需求/资源补充时段。

本会话已使用这些子代理；尚未创建用户侧独立新聊天。当前工具没有创建/分派独立聊天的接口。agent-handoffs.md 提供可直接用于其他会话的任务卡；在工具允许前，使用本会话现有代理执行，不声称已经创建新聊天。

## 任务派发与协作协议

1. 总负责人给任务编号，附原版证据、规格、依赖、文件所有权、提交要求与验收用例。任务卡见 agent-handoffs.md。
2. 代理先确认输入是否完整；缺事实时报告具体缺口，不自行补齐。可独立推进不依赖缺口的部分。
3. 同一文件同一时段只分配一个写入者。共享类型、依赖清单、锁文件、迁移和公共规则由总负责人协调单人变更。
4. 代理交付实际文件与验证结果，不只提交计划或口头结论；主会话审查后统一集成。当前共享工作区不允许代理自行同时提交或推送。
5. 内部浏览器由总负责人排独占时段，交接标签页与当前状态；禁止两个代理同时操作同一角色/页面。多账号需求先说明实际原因，不要求用户重复提供已有信息。
6. QA在实现者报告完成后独立执行，缺陷发回责任人，复测通过才关闭。主会话负责最终状态，而非以代理结束作为项目结束。

状态：TODO → READY → RUNNING → REVIEW → VERIFIED；受阻时为 BLOCKED，记录可恢复条件。功能 VERIFIED 必须具备原版比对与接口、页面两种证据；纯文档任务按其交付要求验收，不计入游戏实现完成率。

## 监控与报告

主会话活动执行期间查看代理状态与消息，按里程碑和新阻塞更新任务板；不为无变化状态反复打扰用户。代理报告包括任务编号、实际改动、证据、验证结果、当前阻塞和下一步。失败先定位原因再派发修复，禁止无差别重跑或多代理互相覆盖。

每个阶段结束汇报：已验证功能数/已发现功能数、未知项数、接口通过数、页面通过数、视觉差异、未关闭缺陷、Git版本。分母尚未稳定时明确说明，不能用代码行数或文档数衡量复刻进度。

会话结束后不声称持续后台监控；当前没有创建定时自动化。用户需要独立新会话时使用交接单，并由主会话汇总可获得的报告。

## 技术决策与风险控制

优先评估 TypeScript 客户端 + Node.js 服务端，但尚未定最终引擎。原版使用Unity不意味着必须同引擎，也不意味着已经拥有原版场景/资源。根据实机确认2D/3D、骨骼、地图、遮挡、镜头、粒子和UI层级后比较Unity/C#与浏览器引擎；不在未核实时锁定Phaser或Babylon.js。

精确资源、随机规则、后期系统、限时活动、多人行为是1:1的关键未知项，按证据分别关闭。素材建立来源与可用性记录，缺原版工程/资源时明确差距。只能观察客户端行为的后台规则不能谎称取得了原版源码。

不预报未经估算的完成日期。M1形成系统、资源和依赖清单后，逐模块估计工作量并滚动修订；任何缩减需求都需用户明确授权。
