# 主场景容器与导航 QA

2026-10-13，Australia/Perth。本轮为本地客户端导航容器，不是完整主场景玩法或原版视觉交付。QA仅只读review并记录合同；不操作浏览器、Grok或Git，不修改代码。

## 可验合同

1. 空存档创建角色成功后进入“江湖”，显示服务返回的真实姓名和参考性别；保存失败不得提前进入成功页面。
2. 已有角色刷新，通过既有GET读取后进入江湖，姓名与性别不得硬编码示例。
3. 江湖“侠客”打开原角色资料；资料可回江湖，原武学图鉴入口和详情返回链保留。
4. 仅当真实GET武学检查点成功时提供可达武学入口；普通新角色没有检查点时不凭空增加武学拥有或完成任务。
5. 武学返回江湖；任务仅显示服务state.task，不添加战斗、发奖或完成任务动作。已有装卸继续走原接口，成功后更新，失败不假成功。
6. 本地容器没有原版地图、角色动画或战斗素材；普通新角能进该容器，不等于自然任务链已连通到事件和人物装备。

## 最终客户端只读 review

客户端通知就绪后，独立读取 `client/index.html` 与 `client/app.js` 的创建/读取、面板切换、检查点读取及原武学动作调用链，未运行浏览器或测试命令。

- PUT角色成功和GET已有角色成功都调用 `showCharacter`；它由响应写入姓名、性别，再调用 `showJianghu`。保存失败走错误提示，不执行成功导航。HTML确有jianghu-panel，且面板枚举包含该节点。
- 侠客按钮打开saved-step，返回江湖绑定showJianghu。图鉴和详情返回链仍分别回图鉴、角色资料。武学返回按钮已改为返回江湖。
- 武学入口HTML默认隐藏；GET检查点成功后才显示。404清空旧equipmentState、槽位、卡片、任务并隐藏入口；当前若在武学页则回江湖。普通角色不会因显示江湖而自动写武学sidecar。
- 检查点请求序号在fetch后、JSON后及catch核对，装卸动作令旧读取失效；这项为代码观察，未做时序实测，不能宣称所有网络竞争场景均已覆盖。
- 任务文本直接来自state.task。新增江湖只有姓名/性别、文本空间和侠客/条件武学导航，没有完成任务、事件判胜、敌人或发奖动作。原装卸仍走既有接口成功响应更新。

本轮静态review未发现阻止上述容器导航交付的问题。没有后端修改输入，因此未重复运行全套API；主会话尚需把真实空目录创建、普通无检查点、已有检查点导航、返回和刷新记录补入本报告。普通角色可达的是占位江湖容器，不是已实现原版主场景移动、剧情、自然任务链、战斗或人物装备。

## 主会话真实页面验收

3004使用全新空路径.local/main-scene-browser/character.json，不设任何武学检查点。内部浏览器选择女、输入“江湖导航验收”、保存后进入江湖，姓名性别与真实PUT响应和磁盘角色一致。点击侠客→武学图鉴→返回角色→返回江湖，再刷新，姓名和女角色保持；武学装配入口隐藏，磁盘未生成martial sidecar。截图evidence/local-main-new-character.jpg。

3003既有双武学角色刷新进入江湖，显示服务端任务；真实点击武学、一键装配、返回江湖及再次刷新，入口和任务保持。截图evidence/local-main-checkpoint.jpg。普通角色进入占位容器通过，不等于正常主线获得技能/进入战斗已实现。

另外使用独立本地3005反向代理，转发3003并只延迟指定GET的响应体12秒，未改游戏服务代码或存档。第一组把第二个武学GET旧状态（上勾1/入悟2）延迟，实际页面进入武学→返回江湖→再进入→一键装配为入悟1/上勾2；等超过12秒旧体返回，页面仍新顺序，截图evidence/local-main-stale-read-ignored.jpg。第二组仅延迟首次武学读取，期间侠客→返回江湖，12秒后武学入口正确出现且可点击往返。两处审查发现的竞态均经真实页面验证。

初版测试代理同时延迟响应头，会使后续同URL读取等待，首次点击因按钮仍禁用而超时，未计为通过；改为先发送no-store响应头、只延迟已捕获响应体后，才执行并通过上述乱序场景。代理脚本.local/navigation-race-proxy.mjs为临时测试工具，测试后已停止，页面恢复3003正常服务。未借助宿主机浏览器。
