## 当前资产结论

当前 `client/` 只有 HTML、CSS、JS，没有独立角色图、背景图、图集、字体、动画或音频文件。现有客户端以系统字体、纯色、圆形文字标记和 DOM 表单实现；角色流程与图鉴数据可用不代表原版美术已还原。`docs/evidence/` 的图片是截图证据，不是独立原资产；被角色、文字、遮罩或按钮盖住的区域无法由截图完整恢复。

下表“独立素材缺”表示本次盘点未在客户端或证据目录找到可直接接入的独立素材，不等于原站不存在，也不声称已经获得原站文件或下载地址。可仿制的框线、布局和纯色也应保留“本地重建”来源标识，不能当作拿到了原资产。

## 面向美术还原的交付顺序

1. **先解决创角主体**：VA-02～06、VA-16。交付透明男/女角色、无遮挡背景、必要控件及字体策略；以原版相同尺寸对齐轮廓、比例、坐标和文字，而非继续扩展通用表单。若只能重建，逐项注明重建和未一致细节。
2. **再解决武学视觉**：VA-13～15。交付图层化背景、技能图标和组件状态；当前只读图鉴可以替换为这些真实独立组件，交互仍不得超出已确认规则。
3. **接主场景与剧情**：VA-08～12、VA-17～21。需要地图、角色资源与动态/声音证据共同完成，不能以静态背景加按钮代替完整玩法。
4. **补选服与全流程状态**：VA-01、03、07，并对各页面的加载、遮挡、返回、不同窗口尺寸逐项对比。未探索页面另建条目，不能以本清单已列项目代表全游戏覆盖。

每个实际素材交付至少登记：关联 VA 编号、证据位置、独立文件相对路径、来源（原资源/本地重建）、尺寸/透明通道、缩放/锚点、状态或动画时序、仍缺内容。尚无文件就填“缺”，不编造 URL、文件名或已获资源。验收需逐区域对照和动态采样；整屏截图只能作参考，不能作为可交互游戏界面或持有全部原资产的证明。
